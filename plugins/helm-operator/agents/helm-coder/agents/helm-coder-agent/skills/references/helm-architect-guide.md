## 2. Pod Security and Network Design Guidelines

To comply with Bitnami hardening standards, all generated charts must enforce:
*   `runAsNonRoot: true` and `runAsUser: 1001` under the Pod's `securityContext`.
*   `readOnlyRootFilesystem: true`, `allowPrivilegeEscalation: false`, and `capabilities.drop: ["ALL"]` under the container's `securityContext`.
*   A default-deny `NetworkPolicy` to restrict ingress/egress unless explicitly configured.
*   Required CPU/Memory limits. Container resource configurations must never be omitted.

## 3. Health Probes Configuration

All long-running web application workloads must expose:
*   **Liveness Probe:** Period of 10s, timeout of 5s, initial delay matching typical framework boot time (e.g., 30s for Java, 5s for Go).
*   **Readiness Probe:** Period of 10s, timeout of 3s, checks target endpoint health before adding the pod to Service endpoints.
